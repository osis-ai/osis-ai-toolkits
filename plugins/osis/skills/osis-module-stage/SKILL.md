# osis-module-stage

> 施工阶段模块。决定有多少个阶段、每个阶段激活/钝化哪些组,处理体系转换时序。具体阶段序列、时长以桥型 SKILL 和项目画像为准,本模块只写跨桥型通用的规律。

## 接到任务后,按顺序做

1. **从桥型层读取阶段序列**(CS1~CSn 名称、时长、每个阶段的主要动作)。
2. **创建施工阶段**(`stage.create(no, name, duration)`),`no` 必填且必须从 1 连续,没有自动编号。
3. **在返回的 Stage 对象上调 `define_element` / `define_boundary` / `define_loadcase` / `define_analysis`**(不是在 manager 上),定义该阶段激活/钝化的内容。
4. **把阶段编号、时长、激活清单写入建模状态**。

## 写法

```python
stg = engine.stage.create(1, "CS1_主梁预制", 7)
stg.define_element(1, 1, "预制单元", 7.0, 0)     # op, type, 组名, 龄期 birth, part
stg.define_boundary(1, 1, "临时支座")            # op, type, 边界组名
stg.define_loadcase(1, 1, "", "预制单元自重")    # op, type, ref_lc_name, lc_name
stg.define_analysis(1, "LIVE", "车道荷载包络")   # op, 分析类型, 工况名
```

- `op`:1=添加、0=移除;`type`:1=激活、0=钝化。
- `define_element` 的 `birth` 是激活时的龄期(天),移除时传 `None`:弹簧单元组(`create_spring`)用 `0.0`;混凝土单元组用激活时的龄期(预制梁即存梁/张拉龄期)。设错会报"弹性连接报错"或激活时间不对。
- `define_loadcase` 的第 3 个参数 `ref_lc_name` 一般传 `""`,第 4 个才是工况名。
- `define_analysis` 的类型:`MODAL` / `SETL` / `RSPEC` / `LIVE` / `BUCKLE`。
- 改阶段名:没有 `rename`,用同 `no` 重新 `create(no, 新名, duration)` 覆盖。
- 插阶段 `stage.insert(ref_no, position, name, duration)`,`position`(0=前插、1=后插)必填;`stage.delete(no)` 参数是编号 int。
- 阶段工期是属性 `.duration`(没有 `get_duration()`)。
- **单跑 `_10`**:已有阶段上重跑 `define_*` 会报「同一阶段内不允许重复激活单元组」,单跑前先 `engine.stage.clear()`,或直接跑 `main.py`。

## 序列骨架

| 体系 | 骨架 |
|---|---|
| 预制简支 | 预制张拉 → 存梁 → 二期恒载 → 收缩徐变 → 运营 |
| 先简支后连续 | 预制张拉 → 存梁 → 墩顶现浇 + 负弯矩束 → **体系转换** → 二期恒载 → 收缩徐变 → 运营 |
| 支架现浇 | 整体浇筑 + 张拉 → 二期恒载 → 收缩徐变 → 运营 |
| 悬臂浇筑(梁/刚构) | 下部及 0 号段 → 各节段(挂篮 → 浇筑 → 张拉)循环 → 边跨合龙 → 中跨合龙 → 二期恒载 → 收缩徐变 → 运营;体系转换落在合龙阶段 |

- 阶段数随节段数变化,不要预设固定阶段数;运营阶段时长 0。
- 阶段名用 `CS{n}_{动作}`,如 `CS1_主梁预制`;动作由桥型层给。

## 体系转换

- 体系转换阶段**一次性完成**所有激活/钝化,拆到多个阶段会导致结构不收敛或成机构。
- 典型激活:永久支座、桥墩弹簧、永久固结(刚构);典型钝化:临时支座、临时支架、临时锚固。
- 具体哪些组在哪个阶段切换,由桥型 SKILL 的支座方案决定。

## 写 `_10` 前的引用核对(必做)

`_10` 不创建任何对象,只按名字引用 `_6`/`_7`/`_8`/`_9` 已创建的组、工况、分析。落笔前打开实际文件逐项核对,**全部命中才写**:

| `define_*` 参数 | 必须逐字等于 |
|---|---|
| `define_element` 的组名 | `_6` 中 `element.group.create(...)` 的组名 |
| `define_boundary` 的组名 | `_7` 中边界组名 |
| `define_loadcase` 的 `lc_name` | `_8` 中 `engine.load.create(<名>, ...)` 的工况名 |
| `define_analysis` 的工况名 | `_9` 中分析工况名 |

- **工况名 ≠ 钢束名**。`define_loadcase` 只引用 `_8` 的工况名(如 `预应力腹板束`),不引用钢束 shape 名(如 `N1-1`)。
- 桥型层给定的工况名是 `_8` 与 `_10` 之间的契约名,两处逐字出现,不得同义改写。

## 失败模式

- **阶段编号不连续** —— 中间缺号报"阶段不存在"
- **组名不存在** —— 引用的单元/边界组名不在 `_6`/`_7` 中,或差字符
- **`该工况中不存在名为 xxx 的预应力板束/荷载`(命令流 `StgLC,...`)** —— 引用了 `_8` 未创建或拼写不一致的工况名,或误把钢束 shape 名当工况名。对照 `_8` 的 `load.create` 改到逐字一致后写回(见 `osis-engine` §失败修复流程)
- **体系转换时序错** —— 永久约束在临时锚固之前激活,结构超静定异常
- **钢束张拉阶段早于构件激活** —— `layout` 报"钢束进入未激活单元"
- **`同一阶段内不允许重复激活单元组[xxx]`** —— 同阶段重复 `define_element`,或单跑 `_10` 前没清阶段。删重复行,或按上面先 `stage.clear()`

(其他见 `osis-engine/references/error_diagnosis.md`)
