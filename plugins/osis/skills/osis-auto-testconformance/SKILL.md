# osis-auto-testconformance

> 完整建模(含模板复制/小修)写回成功后,由总控自动跑一次,不需要用户开口;"越快越好"也不省略。局部修改、`osis-edit-hmid` 不跑,除非用户要求。
> 评测对象:**OSIS 里的模型,不是代码**。脚本把当前实例的模型导出为求解器命令流(`export_apdl`),用 pyosis 自带的 `transfer` 转回模板结构的 prep 代码(临时目录,不碰工程),再评分。代码怎么写(变量、循环、辅助函数、另一种 API)不影响得分。

## 两套评分

| | 构造评分 | 受力评分 |
|---|---|---|
| 评什么 | 尺寸和布置是否落在工程经验区间 | 求解结果有没有大错:预应力、反力、荷载、挠度、应力 |
| 要不要求解 | 不要,只读模型 | 要,在临时工程里求解,不动当前实例 |
| 脚本 | `scripts/test_conformance.py` | `scripts/test_mechanics.py` |
| 维度 | 构造 D1~D5,含义按桥型不同 | 受力 D1~D8,各桥型相同;按档位评 5 / 7 / 8 项 |
| 总分 | 五项加权和,满分 1.0 | 各项取最低,满分 1.0 |
| 耗时 | 几秒 | 快速档几秒到一分钟;另两档见 §受力评分 |

- 两套分**各出各的总分,不合并**。两边的维度都叫 D1、D2……,向用户汇报时带上"构造"或"受力"。
- 单项状态、总评级、退出码两套相同:单项 ≥ 0.9 符合要求(ok)/ ≥ 0.5 基本符合(warn)/ < 0.5 不符合(fail);总分 1.0 优秀 / ≥ 0.8 良好 / ≥ 0.6 合格 / ≥ 0.4 待改进 / 其余不合格;退出码 `0` = 总分 ≥ 0.5,`1` = 总分 < 0.5,`2` = 没评成。
- 各项的区间、阈值、依据见同目录 `评分说明.md`。

| 干 | 不干 |
|---|---|
| 构造评分:按桥型规则评构造合理性 | 验算荷载组合 / 规范 → `osis-check` |
| 受力评分:求解后评恒载 + 预应力下的受力 | 评活载、温度、沉降的效应,评承载力 |
| 出总分 + 分项 + 状态 + 原因 + 建议 | 改任何代码或模型(只读不写;受力评分在临时工程里算) |

## 工作流

```
模型写回 OSIS(跑过 prep/main.py)
    │
    ▼
构造评分:execute_python 跑 test_conformance.py(调用方显式给 bridge_type / is_continuous)
    │
    ▼
受力评分快速档:test_mechanics.py 准备 → instance_id="solver" 求解 → 清理
    │
    ▼
展示给用户:两套分各自的总分 + 各 D 项 + 状态 + 原因 + 建议
```

`<skill_dir>` = 本 SKILL.md 所在目录。两个脚本都用 OSIS MCP 的 `execute_python` 跑(工具名可能带宿主前缀,按后缀认):它用 OSIS 环境的 Python,自带 pyosis,连到指定实例,读到的就是该实例的模型。`execute_python` 不收命令行参数,用 `sys.argv` + `runpy` 传。总分 < 0.5 时脚本退出码 1,`execute_python` 返回 `ok=false`(`SystemExit: 1`),报告仍在 stdout 里,照常读。

## 构造评分

### 调用方必传的参数

| 参数 | 含义 | 取值 |
|---|---|---|
| `bridge_type` | 桥型 | cantilever_box / rigid_frame / t_girder / precast_small_box / cast_in_place_box / hollow_slab |
| `is_continuous` | 是否连续梁 | true / false |

可选:`expected_L`(仅当节点提取不到主跨时兜底)、`is_prestressed`、`concrete_ratio`、`beam_width`——知道就传,不传规则按模型提取值兜底。主跨 L 从节点 / 支座几何提取,不要从目录名猜。

### 用法

```python
import runpy, sys
script = r"<skill_dir>/scripts/test_conformance.py"
sys.argv = [script, "--bridge-type", "precast_small_box", "--is-continuous", "true"]
runpy.run_path(script, run_name="__main__")
```

导出失败(退出码 2)多半是模型还没写回 OSIS:先跑 `prep/main.py` 再评。

**读代码模式(只在没有 OSIS 时用)**:`--candidate-dir <工程的 py/ 目录>`(或模板目录,下面要有 `prep/`;给 `prep/` 本身会报错)。读的是代码,只有代码与模型一致时结果才可信:

```bash
python <skill_dir>/scripts/test_conformance.py --candidate-dir <py 目录> --bridge-type cantilever_box --is-continuous true
```

**可选参数**:
- `--expected-L FLOAT` — 节点提取不到主跨时的兜底
- `--is-prestressed BOOL` — 是否预应力
- `--concrete-ratio FLOAT` — 混凝土折算厚度 m³/m²
- `--beam-width FLOAT` — 桥宽 m
- `--output PATH` — 报告写到文件(默认 stdout)
- `--no-auto-detect` — 没传 `--bridge-type` 且目录名猜不出桥型时报错,不用 unknown 兜底
- `--list-bridge-types` — 列支持的桥型并退出

### 维度(按桥型)

所有桥型都出构造 D1~D5 五项,名称同报告标题,各项含义按桥型不同:

| 桥型 | 目录名兜底关键字 | D1 | D2 | D3 | D4 | D5 |
|---|---|---|---|---|---|---|
| cantilever_box | 悬浇/悬臂 | 支点梁高 | 跨中梁高 | 悬浇段梁高变化曲线 | 截面常规尺寸合理性判断 | 经济性与合理性 |
| rigid_frame | 刚构 | 支点梁高 | 跨中梁高 | 悬浇段梁高变化曲线 | 截面常规尺寸合理性判断 | 经济性与合理性(含边中跨比、墩高,无 D6) |
| t_girder | T 梁 / 矮 T 梁 | 跨径适配性 | 高跨比 | 截面常规尺寸 | 建设期经济性 | 标准化模板化指标 |
| precast_small_box | 小箱梁 | 跨径适配性 | 高跨比 | 截面常规尺寸 | 建设期经济性 | 标准化模板化指标 |
| cast_in_place_box | 现浇箱梁 | 跨径适配性 | 高跨比 | 截面定义 | 施工阶段 | 结构完整性 |
| hollow_slab | 空心板 | 跨径适配性 | 高跨比 | 截面常规尺寸 | 截面经济性(空心率) | 建设期经济性 |
| unknown | 不匹配任一 | 只评结构完整性,总分最高 0.2(必然不通过) | | | | |

T 梁按跨中马蹄自动分流:bh≤tw+2cm→矮T。

上表关键字**仅供兜底**:没传 `--bridge-type` 时才用 `detect_bridge_type(工程名)` 猜。大多数工程名不含桥型信息,猜不中会回退 `unknown`,分数失真——所以必须显式传桥型。

### 输出格式

markdown 报告大致形如(满分 1.0):

```
# <工程名> 构造建模正确性评定报告

## 项目概况
- 候选目录:<工程名>
- 桥型:cast_in_place_box
- 主跨 L:25.0 m
- 根部梁高 H_root:2.2 m
- 跨中梁高 H_mid:1.5 m
- 底板厚:T_root=0.22 m, T_mid=0.22 m
- 阶段数:4
- 总分:0.80 / 1.0
- 评级:良好 / Good

## 分项检查

### 2. D2 高跨比:0.00 / 1.0
- H/L:0.088
- 合理 H/L 区间:[0.0455, 0.0667]
- 状态:不符合
- 原因:H/L=0.0880 不在经验区间 [0.0455, 0.0667](H=2.2, L=25.0)
- 建议:建议调整梁高,使 H/L 落在合理区间

>>> model_conformance 总分: 0.8000  (满分 1.0)
```

## 受力评分

模仿工程师的做法:建完模先算一点结果,大差不差再往下走。**不需要懂钢束**:脚本拿"合计"减"恒载"得到预应力的效应。

### 三档

| 档 | `--tier` | 怎么算 | 评的维度 | 求解耗时(另加约 10 s 启动) |
|---|---|---|---|---|
| 快速档(缺省) | `fast` | 所有施工阶段压成一个阶段 | 受力 D1~D5 | 空心板 / 小箱梁 / T 梁 / 现浇箱梁 1~15 s;悬浇 5~25 s;刚构 10~70 s |
| 施工阶段档 | `stage` | 保留施工阶段,算到成桥为止;去掉徐变十年和运营阶段(温度 / 沉降 / 活载) | 受力 D1~D7 | 轻型桥 2~20 s;悬浇半分钟到几分钟;刚构 2~10 min |
| 完整档 | `full` | 全部阶段原样求解 | 受力 D1~D8 | 同一次全量求解 |

- 施工阶段档在成桥(二期恒载后)时刻的结果与完整求解一致。快速档压成一个阶段后,有体系转换的桥(简支变连续、悬浇)内力分布不对,所以不评应力。
- 完整档只比施工阶段档多评一项长期应力;活载、温度、沉降的结果它算了但不评,那是 `osis-check` 的事。

### 维度(各桥型相同)

| 维度 | 快速 | 施工阶段 | 完整 | 满分条件 | 查什么 |
|---|---|---|---|---|---|
| D1 混凝土等级 | ✓ | ✓ | ✓ | ≥ C40 | 预应力构件的混凝土等级 |
| D2 预应力平衡度 | ✓ | ✓ | ✓ | 预应力弯矩 ÷ 恒载弯矩 ≥ 0.8 | 钢束漏张、张拉应力或根数偏小、线形放反 |
| D3 支座反力 | ✓ | ✓ | ✓ | 没有负反力 | 支座脱空、约束重复 |
| D4 荷载总量 | ✓ | ✓ | ✓ | 竖向反力合计 ÷ 结构自重在 0.95~2.2 | 自重没加、容重或二期恒载的量级错 |
| D5 恒载挠度 | ✓ | ✓ | ✓ | 挠跨比在 1/20000~1/250 | 弹性模量、截面尺寸的量级错 |
| D6 成桥应力 | | ✓ | ✓ | 拉应力 ≤ 0,压应力 ≤ 0.5 fck | 成桥时预应力不足或过大 |
| D7 施工阶段应力 | | ✓ | ✓ | 拉应力 ≤ 1.15 ftk,压应力 ≤ 0.7 fck | 张拉顺序、临时荷载与支承 |
| D8 长期应力 | | | ✓ | 同 D6,取徐变十年后 | 长期预应力储备 |

非预应力结构(`--is-prestressed false`)不评 D1、D2。有几项算几项,总分取各项最低。

### 什么时候跑哪档

- 完整建模后的自动评测:构造评分之后接着跑**快速档**。
- 快速档通过、用户接下来要全量求解或要看应力:先跑**施工阶段档**。悬浇 / 刚构跑之前告诉用户大约要几分钟。
- 用户要看长期(徐变十年后)的应力,或本来就要全量求解:跑**完整档**。
- 某一档不通过:先按报告里的建议改模型再重跑这一档,不要直接上更高的档或全量求解。
- 没算成(退出码 2,比如求解器未授权):在完工报告里写明"受力评分未执行"和原因,构造评分照常报。

### 三步(前两步连的实例不同,合不成一步)

**第 1 步 准备**,在**当前实例**上跑,把模型导出到临时工程 `<工程目录>/_mechanics/model`(同构造评分的导出方式,不碰工程):

```python
import runpy, sys
script = r"<skill_dir>/scripts/test_mechanics.py"
sys.argv = [script, "--tier", "fast"]
runpy.run_path(script, run_name="__main__")
```

stdout 里有一行 `[next] 用 execute_python 跑第 2 步: instance_id="solver", file=r"...", cwd=r"...", timeout=...`。

**第 2 步 求解**,照那一行调 `execute_python`:`instance_id="solver"`、`file`、`cwd`、`timeout` 原样传。OSIS 内部 Agent 的 `execute_python` 没有 `instance_id` 参数，改传 `solver=true`。stdout 就是报告。

**第 3 步 清理**,读完报告后在当前实例上跑(施工阶段档和完整档的求解输出可达几个 GB):

```python
import runpy, sys
script = r"<skill_dir>/scripts/test_mechanics.py"
sys.argv = [script, "--cleanup"]
runpy.run_path(script, run_name="__main__")
```

**可选参数**:
- `--tier fast|stage|full` — 档位,缺省 `fast`
- `--concrete-grade INT` — 主梁混凝土等级(如 50);缺省取模型里最高的等级,主梁不是最高等级时要传
- `--is-prestressed BOOL` — 是否预应力结构(缺省 true);false 时不评 D1、D2
- `--scratch PATH` — 临时目录,缺省 `<工程目录>/_mechanics`;第 3 步要传同一个
- `--candidate-dir PATH` — 读代码模式:工程的 `py/` 目录。没有打开的 OSIS 时用,第 1、3 步可直接用 python 跑
- `--timeout INT` — 求解超时秒数,缺省 3600

### 输出格式

```
# <工程名> 受力评分报告

## 项目概况
- 档位:施工阶段档(算到成桥,不算徐变十年和运营阶段)
- 评分维度:D1、D2、D3、D4、D5、D6、D7,共 7 项
- 施工阶段:原 5 个,求解 3 个;求解 3.9 s
- 混凝土等级:C50
- 总分:0.73 / 1.0(各项取最低)
- 评级:合格

## 分项检查

### 2. D2 预应力平衡度:0.73 / 1.0
- 结果:0.72(单元 14:预应力弯矩 -5533 kN·m,恒载弯矩 7701 kN·m)
- 状态:基本符合
- 原因:预应力只抵消了恒载弯矩的 72%,正常不低于 80%
- 建议:检查钢束:预应力工况是否在施工阶段里激活、张拉控制应力、钢束根数与束数、钢束线形是否偏到了截面另一侧

>>> mechanics 总分: 0.7280  (满分 1.0)
```

### 受力评分查不出的

抗弯 / 抗剪承载力不足、活载下的抗裂、温度和沉降的效应——这些要求解后用 `osis-check` 验算。受力评分通过只说明"受力上没有大错",报告给用户时照这个意思说。

## 注意事项

- **先写回再评**:评的是 OSIS 里的模型。改了代码没重跑 `prep/main.py`,评到的是旧模型;模型是空的则构造评分所有 D 项 = 0,无意义
- **构造评分不用求解**:只读模型的命令流。受力评分要求解,但在临时工程 `_mechanics/model` 里用仅求解器模式算,当前实例的模型、施工阶段和已有结果都不动
- **桥型由 AI 传入**:构造评分的 `bridge_type` / `is_continuous` 显式传;目录名解析只是兜底。受力评分不分桥型
- **主跨从节点提取**:不要用目录名或 `spans_from_name` 猜 L
- **只读不写**:出错(`fail`)只汇报,不自动改;导出写在临时目录,不动工程里的文件
