# 钢束优化

目标：在验算通过的前提下少用钢、让应力储备沿桥长均匀。只在用户明确要求时做。

只有最后的复核要求解：用钢量从 `py/prep` 代码算，现状储备读已有验算结果，方案效果用截面公式估。整个优化只多一轮求解 + 验算。

## 前提

- 模型已求解、已跑 `py/post/main.py`，`Check/` 里是本次结果（旧 `.lcc` 先清掉）。没有就先按 SKILL 步骤 1–3 跑一遍
- `py/prep` 与 OSIS 里的模型一致（在界面里改过钢束就先导回代码），否则用钢量和改动都会对不上
- 现状有 NG 时先说明。由钢束多少引起的 NG（如压应力超限）可以并进优化方案一起消；其他原因的 NG 走 SKILL 修改流程

## 步骤

1. **现状用钢量**：`python scripts/tendon_steel.py`，得到各类钢束规格、束数、根数、用钢量和共用规格
2. **现状储备**：按桥型 SKILL §钢束优化 的分区，从本次 `.lcc`（`scripts/load_lcc.py --list` 看有哪些表、再看列名）取每区上下缘：
   - **先定上下缘，再填表**：验算表的应力列名不代表上下缘，**Sig_B 不是底缘**（65+118+65 实测：Sig_B 是应力点 1、3，在截面顶）。用 `engine.section.get(no).stress_points` 读应力点坐标判断：截面以梁顶为参考线，y≈0 是上缘，y≈−梁高 是下缘。回复里写明每列对应哪一缘、依据是什么
   - 压应力储备：频遇组合下的最小压应力（压为正）
   - 压限余量：限值（0.5fck）减去标准组合最大压应力
   - 施工阶段：桥型 SKILL 点名的控制阶段的上下缘应力
   - 用户或项目画像没给储备下限时不自定阈值：硬约束只用规范限值，"均匀"只比较各区储备的高低差
3. **估算**：每类钢束每束增减 1 根，对各分区上下缘的应力增量
   - 只算经过该截面的钢束（按曲线 x 范围判断）：悬臂束只经过墩到其锚固节段之间
   - Δσ = ΔN/A ± ΔN·e/W，ΔN = 单根有效预应力 × 140 mm²。有效预应力取钢束结果，没有就按张拉控制应力的 75% 估
   - 二次效应、损失变化、徐变重分布不计，回复里写明是估算
   - 同一截面、同一缘的各个量（最大压应力、储备、余量）用同一个 Δσ 去推，数字要前后自洽
   - **不做敏感性扫描、不开多个 OSIS 实例**；需要验证的交给第 6 步那一轮
4. **方案**：给 2–3 个（保守 / 均衡 / 积极），只改每束根数，不改线形、束长、束数。每个方案列：
   - 改哪几类、从几根改到几根、要新建哪些规格（共用规格要拆）
   - 省钢 t 和百分比
   - 各分区储备和压限余量的估算值
   - 桥型 SKILL 点名的施工阶段控制量
   - 长期挠度的预计变化（桥型 SKILL 要求时）
   
   然后**停下等用户选**
5. **修改**：按 `osis-module-tendon` §改每束根数 改 `_8`，跑 `main.py` 写回
6. **复核一轮**：重新求解 → `py/post/main.py` → 导出。验算项和修改前一致
   - 抗弯、抗剪等承载力项不参与估算，只在复核时对比修改前后的 NG 数
   - 复核出现新 NG：报告位置和原因，给一个退一步的方案（如少减 1 根），等用户决定，不自行反复迭代
7. **对比表**：修改前、修改后两列，含：
   - 用钢量（t）
   - 各分区最小压应力储备、压限余量
   - 各验算项 NG 数
   - 长期挠度（桥型 SKILL 要求时）

   用户要文件就存 csv 到项目目录

## 桥型差异

能调哪几类束、各类束管哪段、分区怎么划、施工阶段看什么，写在各桥型 SKILL 的 §钢束优化。桥型 SKILL 没写时，按结构概念说明假设，并告诉用户这是通用做法。
