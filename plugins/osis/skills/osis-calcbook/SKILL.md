# 计算书生成

模板是用户自己的格式(样式、编号、页眉页脚、目录、公式都要保留),所以**不转换格式,在 DOCX 上原位改字**。
你的工作是通读模板,判断每处内容属于哪一类,写成一份**映射** `mapping.json`,由 `docx_fill.py` 执行。

| 模板内容 | 映射里写 |
|---|---|
| 通用内容:规范条文、公式说明、计算方法、章节标题 | `keep` 或不写 |
| 原项目的数据或描述,OSIS 导出里有对应数据 | 引用 `{{字段}}`,不写具体数值 |
| 原项目的数据或描述,OSIS 没有(工程概况、设计单位、日期、基频、桥梁等级…) | `【待填写：说明】`,生成时自动标红 |

映射里只有引用和占位,不含本项目的具体数值,所以同一个模板换个项目还能用,可以打包成插件(第 6 步)。

没有上传模板时,用 `<skill_dir>/templates/` 下的案例,默认 `OSIS计算书案例.docx`。

## 流程

所有命令在**项目根目录**(与 `py/` 同级)执行,`json/`、`image/` 路径都相对这里。

### 1. 导出 OSIS 数据

验算结果是计算书的主要数据来源。用户还没验算的,先加载 `osis-check` 完成验算。

```bash
python <skill_dir>/scripts/data.py -o 项目数据结构.json
```

`项目数据结构.json` 的字段(引用时用 `.` 连接,如 `基本信息.节点数量`):

- `基本信息`:`节点数量` `单元数量` `边界条件数量` `施工阶段数量` `版本号`;`自重系数`
- 表格数据:`材料参数` `边界条件` `施工阶段` `钢束属性` `钢束坐标` `梯度温度` `收缩徐变` `支座反力`,值为 `json/xxx.json` 或 `null`(模型里没有)
- `验算表格.<验算名>`:`path`、最值(`最小弯矩` `最大弯矩` / `最小剪力` `最大剪力` / `最不利应力` / `最大压应力` / `最大拉应力`,已换算成 kN·m / kN / MPa)、`满足规范`
- `图片文件.<图名>`:`image/IMG_xxx.jpg`,OSIS 原生出的图

验算名、图名以本次生成的文件为准。每个 `json/xxx.json` 是 `{"header": [...], "data": [[...], ...]}`,先看 header 再写 `columns`。
图片只用 `图片文件` 里的,不要自己画图(matplotlib 等)或另发 OSIS 命令出图,计算书里的图要和 OSIS 原生风格一致。

### 2. 提取模板文字

```bash
python <skill_dir>/scripts/docx_fill.py extract "模板.docx" -o 模板文本.md
```

**通读全文**。每段有编号 `P12`(页眉页脚是 `header1:P1`),表格 `T3`(行号 `r0`、`r1`…,每格带段落编号),图片 `I2`。
Word 图表(midas 风格模板的包络图多是这种)也编 `I` 号,标"Word 图表(可换成图片)",换图时整个换成图片。
`〔含公式,不可改〕` 的内容只能保留;`〔含域〕` 的段落(题注、目录)可以 find/replace 改普通文字,不能整段重写。

### 3. 写映射 `mapping.json`

JSON 列表,每项一种操作:

```json
[
  {"id": "P59", "text": "【待填写：工程概况（桥位、桥型、建设单位）】"},
  {"id": "P100", "find": "15", "replace": "{{基本信息.节点数量}}"},
  {"id": "P94", "find": "Osis5.00.00", "replace": "OSIS {{基本信息.版本号}}"},
  {"id": "P595", "find": "-317.2", "replace": "{{验算表格.正截面抗弯承载能力验算.最小弯矩|.1f}}"},
  {"id": "P595", "find": "验算不满足", "replace": "验算{{验算表格.正截面抗弯承载能力验算.满足规范|满足:不满足}}"},
  {"id": "P315", "find": "f=7.51Hz", "replace": "f=【待填写：结构基频】Hz"},
  {"table": "T1", "from_row": 1, "json": "{{材料参数}}"},
  {"table": "T3", "from_row": 1, "json": "{{施工阶段}}", "columns": ["序号", "名称", "持续天数(d)", "累计天数(d)"]},
  {"table": "T9", "from_row": 1, "json": "{{材料参数}}", "filter": {"材料名称": "^C[0-9]"},
   "columns": ["材料名称", "弹性模量", null], "scale": {"弹性模量": 1e-6}},
  {"image": "I1", "path": "{{图片文件.计算模型图}}"},
  {"id": "P63", "keep": true},
  {"table": "T8", "keep": true}
]
```

| 操作 | 说明 |
|---|---|
| `find` / `replace` | 段内替换,其余文字和格式不动。`find` 写模板原文,在段内必须唯一,不唯一就写长一点,或加 `"all": true` |
| `text` | 整段重写,保留段落格式。段内有域/图片/公式时不允许 |
| 表格 `json` | 从 `from_row` 起的原数据行换成 json 的行,样式照抄 `from_row` 那行。表头占两行时 `from_row: 2`;末尾合计行要保留时加 `to_row`(第 `to_row` 行起保留) |
| 表格 `columns` / `filter` / `scale` | `columns` 按名字选列,顺序即表格列顺序,`null` = 该列留空(OSIS 无此数据),格数必须等于样板行格数;`filter` 按列值正则筛行;`scale` 按列乘系数换单位 |
| 表格 `rows` | 直接给行,格子里可以写引用。只用于 OSIS 没有 json、但能由几个字段拼出的小表 |
| `image` | 换图(图片或 Word 图表都行),保持原显示宽度,高度按新图比例。`path` 写 `{{图片文件.<图名>}}` |
| `keep` | 看过、原样保留,不再出现在遗留清单里 |

引用 `{{字段|格式}}`:`|.1f`、`|.3g` 等是 Python 数字格式;是/否字段必须写 `|满足:不满足`。
字段为 `null` 或不存在时自动填 `【待填写：字段】`(表格换成一行占位,图片换成占位文字),所以**本项目没数据也照样写引用**,别的项目有数据时就能填上。顶层字段名写错会直接报错。

写映射的要点:

- **模板怎么写,你就怎么写**。模板在这里列了数,你就换成引用;模板只有定性描述,不要自己加数。
- 结论段:数值引用 `验算表格` 的最值,"满足/不满足"引用 `满足规范`,句式不动。
- 模板里的提示语(如"请自行补充相关内容！")也是待填内容:有字段就引用,没有就换成 `【待填写：…】`。
- 图片和 Word 图表按图下方的题注对 `图片文件` 的图名。一个 `I` 都不要漏:`图片文件` 里没有对应图的(如抗扭),也写 `{{图片文件.<题注里的图名>}}`,本项目没有就自动换成占位文字,别的项目导出了这张图就能填上。
- 模板有、OSIS 不输出的内容:换成 `【待填写：…】`,或整段写 `【待填写：本项目无此项，确认后删除本节】`。不删模板内容,删不删由用户定;这样图表编号也不会乱。
- **映射里不写本项目的具体数值和文字**(包括用户这次口头提供的工程概况等),否则复用时会带到别的项目。这类内容在生成的计算书里补。
- 目录在 Word 打开时自动更新。

### 4. 生成

```bash
python <skill_dir>/scripts/docx_fill.py apply "模板.docx" mapping.json -o 计算书.docx
```

- 有任何一条出错时不生成文件,列出全部错误。改映射后重跑,每次都从模板重新生成。
- 报告里的**本项目无数据的字段**:核对字段名是否写对(写错的深层字段名也会落到这里)。
- 报告里的**未处理且含数字的段落**(表格按表汇总):逐个看,原项目的数就改成引用或占位,通用内容加 `keep`,重跑,直到列表里只剩你确认过的内容。

### 5. 交付

告诉用户:计算书路径、填了哪些、还有多少处【待填写】(红字)需要人工补。删除 `模板文本.md`。
不要覆盖用户已有的计算书,文件重名就加后缀。然后问用户:这个模板以后还用的话,要不要做成插件。

### 6. 打包成插件(用户同意时)

一个模板一个插件。插件对当前打开的 OSIS 项目跑 `data.py`,按映射生成 `<项目根>/计算书_<模板名>.docx`(重名加序号),有 GUI,也能命令行调用 `main.py [-o 输出.docx]`。

```bash
D=~/.osisai/plugins/<英文名>        # 如 calcbook_xxy,命名规则见 osis-customize-osisai
mkdir -p "$D"
cp "模板.docx" "$D/"                # 目录里只能有这一个 .docx,文件名就是插件窗口标题
cp mapping.json "$D/"
cp <skill_dir>/scripts/docx_fill.py <skill_dir>/scripts/data.py "$D/"
cp <skill_dir>/assets/plugin_main.py "$D/main.py"
```

然后按 `osis-customize-osisai` 的第 4、5 步生成图标、注册到 `plugins.json`(名称如"××院计算书",detail 写:GUI 点"生成计算书";命令行 `...\<英文名>\main.py [-o 输出.docx]`;需 OSIS 已打开项目并完成验算)。

验证:`python -m py_compile "$D/main.py"`;在当前项目上跑 `python "$D/main.py" -o 插件测试.docx`,确认生成成功、结果与第 4 步一致后删掉测试文件。


**修改已有插件**:映射有问题时改 `~/.osisai/plugins/<英文名>/mapping.json`,用该目录里的模板按第 4 步验证;模板换了就重新走第 2–4 步。

## 数据对应的坑

| 坑 | 正确做法 |
|---|---|
| `material.json` 里混凝土、钢筋、钢绞线都在一张表 | 模板按材料类型分表时(如 midas 模板的混凝土/预应力钢筋/普通钢筋三张表),用 `filter` 按 `材料名称` 筛行(如 `^C[0-9]`、`HRB`、`钢绞线`),以 json 实际名称为准 |
| `td_prop.json` 是钢束规格(根数、面积、波纹管径、摩阻、松弛),不是材料性能 | 放"钢束属性/预应力钢筋特性值"表;钢绞线的 E、密度、线膨胀系数在 `material.json` |
| 没有对应 json 时拿别的表硬凑(如把材料表塞进荷载工况表) | 没有就占位 |
| 验算 json 的列名、单位与模板表头不一致 | 用 `columns` 按模板列顺序选列;对照表头单位检查数量级(如 json 的弹性模量是 N/m²、模板是 MPa),用 `scale` 换算 |
| midas 风格模板的验算章节只有包络图 + 结论,没有逐单元大表 | 不要往里加表;包络图(Word 图表)按题注引用 `图片文件`,改结论 |
| 模板有、OSIS 不输出的验算(抗扭、裂缝宽度、挠度、抗倾覆等) | 结论换成 `【待填写：…】` |
| 用 PowerShell 读写中文文件会乱码 | 用 Read/Write 工具或 Python(utf-8) |
